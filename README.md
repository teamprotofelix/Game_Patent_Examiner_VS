## v2.0 주요 개선점

- **v1의 '에셋 확인 중…' 정지 가능성 해결**: v1은 외부 `atlas.json`을 `fetch()`로 로딩하고 ES Modules를 실행하여 `file://` 직접 열기에서 차단될 수 있었습니다. v2는 모든 게임 로직을 `js/game.bundle.js` **클래식 스크립트**로 제공하며, 아틀라스 JSON을 번들에 포함해 `fetch()` 없이 시작합니다. 이미지 한두 개가 누락되어도 시작을 막지 않고 대체 그림을 사용합니다.
- **HD 스프라이트**: 주인공 3종 **384×384 프레임 / 50프레임씩**, 총 150개 자세. 이미지 생성 원본에서 분리한 캐릭터를 상태별 변위/기울기/스킬 연출로 각 프레임을 개별 제작했습니다. 몬스터 20종 **256×256 / 21프레임씩**, 보스 3종 **544×544 / 28프레임씩**. 가시적 동작 변화는 있으나 100% 독립 수작업 원화 애니메이션 수준은 아닙니다.
- **적 종류 확대**: 일반 몬스터 **14종**, 엘리트 **6종**, 보스 **3종**. 보스 3종의 패턴·스토리 승리 흐름은 유지했습니다.
- **전장 상호작용 5종**: 경험치 결정, 선행기술 아카이브, 회복 하트, 순간이동 포털, 광역 타격 오브젝트. 접근 시 발동되며 새로운 오브젝트가 등장합니다.
- **문헌 스캔 능력**: PC의 **E**, 모바일 **SCAN** 버튼. 4.5초간 적에게 주는 피해 28% 증가, 17초 대기시간. 기존 대시(Space)·궁극기(Q)와 함께 사용합니다.
- **기기별 텍스처 지연 로딩**: 작은 화면에서는 우선 필요한 캐릭터와 적 이미지를 먼저 불러오고 나머지 몬스터·보스 이미지는 등장할 때 로드하여 시작 지연과 초기 메모리 부담을 낮췄습니다.
- **고해상도 WebP 캐릭터 일러스트** 3종, 세계 오브젝트 6종, 자세한 타이틀·보스 배경, 새 적 UI 썸네일 및 대형 아틀라스.
- 기존 v1의 무기 6종, 5단계 강화·진화 3종, 경험치 성장, 로그라이트 선택, 도감, 업적, 3개 스테이지, 이벤트, 로컬 저장을 유지합니다.

## 실행 방법

### 방법 A: ZIP을 풀어서 직접 실행 (v2에서 개선)

1. 이 ZIP을 해제합니다.
2. 최상위 `index.html`을 Chrome 또는 Edge 등에서 직접 엽니다.
3. **작전 시작 → 캐릭터 및 전장 선택 → 선택한 전장에 출격**을 누릅니다.

v2는 JavaScript ES 모듈 및 JSON `fetch()`에 의존하지 않으므로 로컬 파일 직접 실행을 지원하도록 구성했습니다. 브라우저별 `file://` 보안 설정 차이로 웹 오디오 샘플이나 저장 기능에 제약이 있을 수 있으며, 이 경우 효과음은 Web Audio 합성 방식으로 대체됩니다. 가장 일관된 환경은 아래의 로컬 서버 또는 GitHub Pages입니다.

### 방법 B: 로컬 HTTP 서버

- Node.js 설치 시 `npx serve .` 등의 로컬 서버를 이용할 수 있습니다(패키지 다운로드가 필요한 명령은 오프라인에서 적합하지 않을 수 있습니다).
- Python 설치 시 이 폴더에서 `python -m http.server 8000` 실행 후 `http://localhost:8000`을 엽니다.

별도 빌드나 CDN·유료 API·DB·로그인·서버 프로그램은 **게임 실행에 필요하지 않습니다.**

### 방법 C: GitHub Pages

1. ZIP 안의 **모든 파일/폴더**를 GitHub 저장소 최상단에 업로드합니다.
2. GitHub 저장소 **Settings → Pages → Build and deployment → Deploy from a branch**를 선택합니다.
3. Branch: `main`, folder: `/ (root)`를 지정합니다.
4. 제공된 `https://사용자.github.io/저장소/`에서 실행합니다.

GitHub Pages의 저장소 하위 경로에서 동작하는 상대 경로 구조입니다.

**v1으로 이미 배포한 저장소 업데이트 시** 이전 서비스 워커가 v1을 임시로 캐시할 수 있습니다. v2 서비스 워커는 캐시 버전과 탐색 요청 정책을 변경했습니다. 배포 후 화면이 갱신되지 않으면 `Ctrl+Shift+R`로 강력 새로고침하고, 그래도 남아 있다면 브라우저의 해당 사이트 캐시/서비스 워커를 정리하십시오. 사용자 저장 데이터는 별도로 유지하는 것을 권장합니다.

## 조작법

| 입력 | 효과 |
|---|---|
| WASD / 방향키 | 이동 |
| Space / DASH | 무적 회피 대시 |
| Q / ULT | 캐릭터별 강력한 궁극기 |
| E / SCAN | 적 피해량 증가 스캔 |
| Esc / Ⅱ | 일시정지 |
| 마우스·터치 | 메뉴 및 강화 카드 선택 |
| 모바일 왼쪽 드래그 | 가상 조이스틱 이동 |

기본 공격은 자동이며 모바일은 가로모드에 최적화되어 있습니다. 게임을 하는 동안 세로모드에서도 작동하지만 레이아웃 공간이 제한될 수 있습니다.

## 데이터와 성능

- `localStorage` 키는 **v1과 동일**하여 기존 도감·도전 기록·설정의 연속성을 유지합니다. 브라우저가 다른 오리진으로 인식하는 `file://`와 HTTPS 페이지 사이에는 저장 데이터가 자동으로 공유되지 않습니다.
- 주요 아트는 손실 압축된 WebP이며 프레임 좌표는 `assets/atlas.json`에 보관됩니다. `js/game.bundle.js`에는 해당 JSON을 빌드 시 내장합니다.
- PWA는 HTTPS 또는 localhost에서만 동작합니다. `service-worker.js`는 버전 구분, 네트워크 우선 페이지 제공과 선택적 이미지 캐싱을 구현합니다. 실제 오프라인 캐시 동작은 브라우저·캐시 저장 공간에 따라 달라질 수 있습니다.
- 낮은 사양 기기에서는 **설정 → 파티클 품질: 최소**, 화면 흔들림 끄기를 권장합니다. 모바일 60FPS를 모든 기기에서 보장하지는 않습니다.

## 소스 구조 및 재생성

- `js/engine/`, `js/ui/`, `js/systems/`, `data/`: 사람이 편집하는 모듈형 소스
- `js/game.bundle.js`: **실제로 브라우저가 실행하는 단일 클래식 JavaScript**, `python tools/build_bundle.py`로 재생성
- `assets/characters/`, `assets/enemies/`, `assets/bosses/`: 메타데이터가 있는 애니메이션 WebP
- `assets/portraits/`, `assets/props/`: 새 고화질 초상화와 전장 오브젝트
- `assets/source/character_lineup.webp`: 신규 주인공 아틀라스 제작에 사용한 원본 WebP 일러스트
- `tools/generate_v2_art.py`: 캐릭터·적·보스·환경 오브젝트 제작 스크립트 (재실행 시 Python Pillow, NumPy, OpenCV, CairoSVG 필요)
- `tools/build_sw.py`: PWA 캐시 파일 목록 및 서비스 워커 생성
- `tools/asset-validation/validate.py`: 경로·투명도·알파·프레임 경계 확인
- `tests/v2_browser_smoke.py`: 브라우저 게임 로직 스모크 테스트

**중요**: 원본을 변경한 후에는 `python tools/build_bundle.py`를 실행해 `js/game.bundle.js`에 반영해야 합니다. 초상화·스프라이트를 변경하면 `assets/atlas.json`을 갱신하고 서비스 워커를 `python tools/build_sw.py`로 새로 생성합니다.

## 검증 / 알려진 제한

- 정적 구문 검사: Node.js `node --check` 통과.
- 이미지 검사: Python Pillow를 이용해 **에셋 오류 0, 스프라이트 프레임 경계 경고 0** 확인.
- Chromium 자동화: 공개 페이지를 호출하는 대신, **출시용 동일 JavaScript 번들 바이트를 HTML 문서에 주입**하여 UI 로딩 → 시작 → 몬스터 및 오브젝트 생성 → 대시·궁극기·SCAN → 레벨업 → 보스 3종 격파 → 결과 화면 → 재출격과 모바일 크기 레이아웃을 확인. 테스트 중 예외 0건.
- **실제 GitHub Pages 사이트 및 브라우저 `file://` 내비게이션 테스트는 실행 환경의 로컬 주소 접근 제한 때문에 수행하지 못했습니다.** Android/iOS 실기기 성능과 PWA 설치·오프라인 장시간 테스트도 아직 검증하지 않았습니다.
- 캐릭터 아틀라스는 고해상도 원화를 이용한 프레임별 변위·모핑 기반 애니메이션입니다. 수작업 프레임 애니메이션처럼 독립된 관절별 동작을 모두 보장하는 방식은 아닙니다.
